# 通信・復元 技術検証結果

実施日: 2026-09-06。環境: Windows、Node.js v24.19.0。外部パッケージなし。エンジン・サービス導入なし。

## 結果

17試験成功、失敗0。最終実行は約4.00秒。[実行ログ](spike-test-results.tap)、[試験コード](../spike/protocol.test.mjs)。実行時間はゲームの性能や復帰所要時間の保証ではない。

今回の試作はNode.jsの子プロセス2つを実際のUDP loopbackソケットで接続する。確定履歴と保存ACKはUDPを通り、テスト制御/観測はIPCを通る。復帰の責任情報と時刻はテスト制御側から注入している。人間の操作なしに障害検知から再発見・再認証まで動く実装ではない。

## 検証の内訳

| 試験 | 方法 | 確認したこと |
| --- | --- | --- |
| 1–2 履歴照合 | 純粋関数 | 共通prefixの長い方を採用、古い記録で巻き戻らない、分岐/破損/異試合拒否 |
| 3 冪等性 | 純粋関数 | 二重ペナルティなし、通常決着へ加点なし、復帰後の古い期限通知も無効 |
| 4 期限 | 59999/60000/60001/90000 msを注入 | 固定した期限で境界判定、試合敗北は通常得点と別 |
| 5–6 試合 | 純粋関数 | 復帰ペナルティで10勝終了、引き分けでラウンド進行 |
| 7 責任分類 | 観測値を注入 | 片側再起動と責任不明を分ける。実際の通信断識別を証明する試験ではない |
| 8 通信障害 | 実UDP、3送信ごと欠落、重複、2送信ごと100 ms遅延 | 両者の完全履歴が収束、得点重複なし |
| 9 ACK不達 | ゲストの送信を全破棄→解除 | 保存ACKなしでは次ラウンドを開かない |
| 10–11 再起動 | ホスト/ゲストを強制終了、保存ファイルから別プロセス起動 | 同じ役で再接続・収束後、指定した切断側を敗北にする |
| 12–14 保存途中終了 | 一時ファイル半分/置換直前/置換直後で即時process.exit | 置換前は旧状態、置換後は新状態。新しい通常決着がある時は切断加点しない |
| 15 片側だけ最新 | ホストファイルを明示的に旧世代へ戻す | ゲストの長い共通履歴からホスト回復 |
| 16 破損 | 本体JSON破損、本体なし＋一時ファイル | 勝手に正常化/確定せず拒否 |
| 17 分岐 | 両者に異なる勝者の履歴を保存して実UDP接続 | Conflictを検出してホストの進行操作を停止 |

最終ログの障害通信ケースではホストtx=8/rx=7/drop=1、ゲストtx=7/rx=7/drop=1。短い試験の送信順による値であり、パケット損失率の精密な測定ではない。遅延配送は古い状態/ACKの後着を発生させる。

## 初稿から変更した設計

| 初稿の仮説 | 判断・修正 |
| --- | --- |
| 世代番号とハッシュで新しい方を選ぶ | 不十分。同じ世代でも分岐があり、長い記録にも別系統がある。全共通部分を照合し分岐では停止 |
| ホスト送信後に進む | 相手のdurable ACKを得るまで次ラウンドを開かない。ローカル保存済みイベントは再接続で回収 |
| ラウンド番号による重複排除だけで十分 | 通常決着後の復帰も完了記録が必要。さもないと後着の期限切れ要求で試合敗北を誤適用しうる。RecoveryCompletedを追加 |
| 一時ファイル置換で終了に耐える | 今回のプロセス終了ケースでは成立。電源断・ディスク故障・Godotでの同等性は未確認 |
| 切断時刻＋60秒を保存すれば十分 | 境界のルールだけ確認。再起動時の時計継承・自動検知・期限の永続化統合は未検証 |
| 切断側を判定して敗北にする | 通信不達だけでは断定できない。boot変更の証拠と責任不明を分け、例外方針を設計上明示 |

## 試作の制限

- loopbackのみ。実LAN、別家庭、NAT、中継、EOS、ENet、認証は未検証。
- 保存ファイル内は固定match IDとrules version、操作は信頼したテストコントローラーが与える。ハッシュは認証ではなく、不正プレイヤーへの防御を提供しない。
- 全履歴を40 msごと再送する簡易方式。60,000 bytes以上は拒否する。断片化、帯域最適化、長い引き分け試合は対象外。
- 同期するのはラウンドの確定記録。移動、弾道、予測、補間、音などの実時間同期は未実装。
- 選択/カウントダウン/戦闘をopenという1状態へ集約。各画面からの自動復帰は対象外。
- 復帰ticketのoffender/deadline/nowはIPCで指定。60秒の保存や自動タイムアウトを試験済みとしない。
- ホスト再起動時、テストが新しいUDPポートを相手へ教える。実サービスのルーム再発見と認証保持は別途必要。
- 保存障害は制御した終了点で再現。電源断や実ストレージ障害の保証はしない。

## 再現

プロジェクトのルートで `node --test --test-concurrency=1 spike/protocol.test.mjs` または `npm test`。npm installは不要。OSの一時フォルダに試験ごとの保存先を作り、終了時に自分が作った試験フォルダだけを削除する。

次段階はGodot版で同じ故障マトリクスを再現し、自動切断検知・期限永続化・再認証を追加する。その後に別家庭の2台でゲーム単体の接続候補を評価する。ローカル試験成功を根拠に外部接続要件を達成したとは判断しない。
